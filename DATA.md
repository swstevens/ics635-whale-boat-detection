# Data contract

This is what the data lead hands off so the CNN and DETR tracks can train and
be scored on identical data. If something here doesn't match the HIMB data,
change this file and tell the team. Don't quietly work around it.

## Annotations: one COCO json

```json
{
  "categories": [{"id": 1, "name": "whale"}, {"id": 2, "name": "boat"}],
  "images": [
    {"id": 1, "file_name": "xxx.png", "width": 500, "height": 500,
     "scene_id": "<which of the 93 SkySat scenes this chip came from>",
     "date": "YYYY-MM-DD",
     "conditions": {"glare": false, "cloud": false, "wind": "low"}}
  ],
  "annotations": [
    {"id": 1, "image_id": 1, "category_id": 1, "bbox": [x, y, w, h]}
  ]
}
```

- `bbox` is `[x, y, width, height]` in **chip pixel coordinates**, not map coordinates.
- `scene_id` is **required**. Splits and bootstrap CIs are grouped by scene.
- `conditions` is optional, but it's what lets us report results by glare, wind and cloud
  later. Include whatever tags already exist, even if they're rough.
- **Include empty chips** (no whales or boats). Without them we can't measure false
  positives on glare and whitecaps, which is likely the main failure mode.

## Pixels

- **Prototype:** 3-band 8-bit RGB PNGs. Both pretrained models expect that.
- SkySat analytic products are typically 16-bit, so the conversion to 8-bit needs one
  fixed stretch, such as per-band 2nd–98th percentile, applied the same way to every chip.
  Write down which stretch you used.
- Keep the original 4-band (RGB + NIR) chips. NIR is the planned extension for glint.

## Splits

```bash
uv run python -m whaleboat.splits data/annotations/all.json data/splits
```

This splits whole scenes ~70/15/15 and picks the split whose whale and boat
counts are closest to those ratios. Commit `data/splits/split_manifest.json`
(force-add it, since `data/` is ignored) so the test scenes stay fixed. **No one
tunes on test.**
